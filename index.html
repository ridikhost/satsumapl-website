Dlaczego SatsumaOS?

Przemyślana architektura bez zbędnego balastu systemowego.

Gotowy do Flashowania

Wgraj czysty obraz na zewnętrzny dysk SSD w kieszeni USB Enclosure za pomocą BalenaEtcher lub Rufus. Przełóż dysk bezpośrednio do komputera docelowego i uruchom system.

Auto-Resize Disk

Autorski skrypt uruchamiany przy pierwszym starcie wykrywa rozmiar nośnika (np. 500 GB, 1 TB, 2 TB) i automatycznie rozszerza partycję główną do 100% pojemności dysku.

KDE Plasma 6 & Ciemny Motyw

Lekkie, zaawansowane środowisko graficzne z przygotowaną paletą kolorów Satsuma Dark Glass, nowoczesnymi efektami rozmycia oraz zoptymalizowanym zużyciem pamięci RAM.

Zbudowany na Arch Linux

Korzystaj z najnowszych pakietów, jądra Linux, oficjalnych repozytoriów Pacman oraz przeogromnej bazy oprogramowania AUR (Arch User Repository) dzięki zainstalowanemu `yay`.

Plymouth & Fast Boot

Bootloader Syslinux zintegrowany z silnikiem grafik Plymouth gwarantuje płynny, cichy i czysty proces uruchamiania bez rozpraszających komunikatów tekstowych.

Gotowy dla Deweloperów

Preinstalowane pakiety `base-devel`, Git, Python, narzędzia dyskowe oraz przeglądarka Firefox — gotowe do pracy zaraz po pierwszym zalogowaniu.

Instalacja & Kompilacja

Wybierz sposób wdrożenia dostosowany do Twoich potrzeb.

01

Pobierz i Rozpakuj Obraz

Pobierz spakowany plik obrazu systemowego SatsumaOS. Rozpakuj archiwum za pomocą programu 7-Zip (Windows) lub polecenia w terminalu Linux/macOS, aby uzyskać surowy plik disk.img.

unxz satsumaOS-v1.img.xz
02

Sflashuj Dysk SSD w Obudowie USB

Podłącz docelowy dysk SSD włożony do obudowy USB Enclosure. Uruchom program BalenaEtcher lub Rufus, wskaż plik disk.img i rozpocznij proces wgrywania.

03

Przełóż Dysk do Komputera Docelowego

Po zakończeniu flashowania wyjmij dysk z obudowy USB i zamontuj go bezpośrednio w komputerze docelowym (jako dysk NVMe lub SATA).

04

Pierwsze Uruchomienie & Auto-Resize

Włącz komputer. System automatycznie rozszerzy partycję do 100% pojemności dysku w tle. Zaloguj się danymi:

Użytkownik: satsumapl Hasło: 1234
Wymagania Kompilacji: Czysty system Arch Linux jako host, minimum 4-8 GB RAM oraz co najmniej 30 GB wolnego miejsca na dysku na plik `disk.img`.

1. Instalacja pakietów na hoście & Tworzenie Obrazu 

sudo pacman -S --needed arch-install-scripts dosfstools e2fsprogs parted syslinux
dd if=/dev/zero of=disk.img bs=1M count=18432
parted -s disk.img mklabel gpt
parted -s disk.img mkpart primary fat32 1MiB 512MiB
parted -s disk.img mkpart primary ext4 512MiB 100%
LOOP_DEV=$(sudo losetup --find --show disk.img)
sudo partprobe "$LOOP_DEV"
sudo mkfs.fat -F32 "${LOOP_DEV}p1"
sudo mkfs.ext4 -F "${LOOP_DEV}p2"

2. Instalacja Pacstrap & Wprowadzenie do Chroot 

sudo mount "${LOOP_DEV}p2" /mnt
sudo mkdir -p /mnt/boot && sudo mount "${LOOP_DEV}p1" /mnt/boot
sudo pacstrap /mnt base linux linux-firmware base-devel plasma sddm networkmanager firefox plymouth plymouth-kcm sudo git parted e2fsprogs syslinux
sudo genfstab -U /mnt | sudo tee /mnt/etc/fstab
sudo arch-chroot /mnt

3. Konfiguracja Użytkownika, Bootloadera & Skryptu Auto-Resize 

# Tworzenie wybranego użytkownika
useradd -m -G wheel -s /bin/bash twojanazwa
passwd twojanazwa
echo "%wheel ALL=(ALL:ALL) ALL" > /etc/sudoers.d/wheel

# Skrypt auto-resize dysku
cat << 'EOF' > /usr/local/bin/resize-rootfs.sh
#!/bin/bash
ROOT_PART=$(findmnt / -o SOURCE -n)
DISK_DEV=$(lsblk -no pkname "$ROOT_PART")
if [ -n "$DISK_DEV" ]; then
    parted -s "/dev/$DISK_DEV" resizepart 1 100%
    resize2fs "$ROOT_PART"
    systemctl disable resize-rootfs.service
    rm /usr/local/bin/resize-rootfs.sh
fi
EOF
chmod +x /usr/local/bin/resize-rootfs.sh

Często Zadawane Pytania

W prekompilowanym obrazie domyślny użytkownik to satsumapl z hasłem 1234. Użytkownik posiada pełne uprawnienia sudo. Jeśli kompilujesz system samemu ze źródeł, dane ustalasz podczas procedury `useradd`.
W tle dodana jest usługa systemd `resize-rootfs.service`. Przy pierwszym starcie komputera po przełożeniu dysku SSD usługa uruchamia narzędzie `parted` oraz `resize2fs`, rozszerzając partycję główną root do 100% dostępnej przestrzeni fizycznej dysku, a następnie samoczynnie się wyłącza i usuwa.
Tak. Jak w większości standardowych dystrybucji Arch Linux, opcja **Secure Boot** w ustawieniach BIOS/UEFI musi być wyłączona, aby umożliwić rozruch bootloadera Syslinux.
Oczywiście! SatsumaOS korzysta z oficjalnych repozytoriów Arch Linuksa. Możesz w każdej chwili wykonać pełną aktualizację wpisując sudo pacman -Syu lub używając yay.
